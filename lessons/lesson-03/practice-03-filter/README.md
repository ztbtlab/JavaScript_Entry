## 問題

1 週間の気温（℃）の配列から、`filter` を使って **25 度以上の「暑い日」だけ** を取り出す。

```js
const temps = [18, 26, 30, 22, 25, 19, 28];
// ↓ これを filter で絞り込んで
const hotDays = [26, 30, 25, 28]; // 25 度以上だけ
```

編集するのは `main.js` だけ。結果は画面の枠と Console の両方に出す。

## 完成イメージ

- 画面の枠に `暑い日: 26, 30, 25, 28 ℃（4件）` と出る
- Console に元の配列・暑い日・件数が出る

## ヒント

1. まず **「暑い日かどうか」を判定する関数** を作る。`isHot(temp)` は `temp >= 25` を `return` する。これは **`true` / `false`（真偽値）を返す** 関数。
2. `filter` は「条件に合うものだけ残して、**新しい配列を返す**」メソッド。`temps.filter(isHot)` と書くと、`isHot` が各要素に対して呼ばれ、`true` を返したものだけ残る。
3. **25 を含めたい** ので `>=`（以上）を使う。`>`（より大きい）だと 25 ちょうどの日が消えてしまう。
4. 画面表示は `配列.join(", ")` で 1 行にし、件数は `hotDays.length` で取る。

### map と filter の違い（今日の山）

| | `map` | `filter` |
|---|---|---|
| やること | 全部を変換 | 条件で残す |
| 個数 | 変わらない | **減ることがある** |
| 渡す関数が返すもの | 変換後の値 | `true` / `false` |

練習2 の `map`（5 個 → 5 個）と、この `filter`（7 個 → 4 個）を見比べると違いが分かる。

## チェックポイント

- [ ] **動作**: 画面と Console に 25 度以上の配列と件数が出る
- [ ] **filter の理解**: 元の配列 `temps` は変わらず、`filter` が **新しい配列** を返している
- [ ] **真偽値**: `isHot` が `true` / `false` を返している（数値を返していない）
- [ ] **境界**: 25 度ちょうどの日が **含まれている**（`>=` を使っている）
- [ ] **個数**: 絞り込み後は元（7 個）より減っている

## 発展（TODO 5）: filter → map の合わせ技

`filter` で暑い日だけ残したあと、`map` で「26℃」のように単位付き文字列に変換してみよう。

```js
const hotLabels = hotDays.map((t) => t + "℃"); // ["26℃", "30℃", "25℃", "28℃"]
```

「**絞り込んでから整える**」という、`filter` と `map` を続けて使う流れを体験できる。
