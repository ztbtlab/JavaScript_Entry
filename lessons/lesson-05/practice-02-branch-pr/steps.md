## 手順

VS Code のターミナル（`Ctrl + @` / Mac は `Control + @`）で、リポジトリのフォルダにいることを確認してから始める。

番号は**黒板（スライド）の流れ図と同じ**。詰まったら「いま図のどこ？」で確認できる。

```bash
# ⓪ 準備: いま main にいることを確認する
git ____            # ヒント: いまいる枝の一覧を出すコマンド

# ① 作業用の枝を作って乗り移る（xx は講師が配る記号に置き換える）
git switch ___ feature/lesson-05-xx

# ② profile.js の favoriteThing を自分の好きなものに書き換えて、保存する
#    ⚠️ 書くのは「好きなもの」。名前・学校名は書かない
git ___ .
git commit -m "#__ profile を更新"     # ← __ には練習2 の Issue 番号

# ③ GitHub に送る（初回なので送り先を教える印が要る）
git push __ origin feature/lesson-05-xx

# ④ GitHub の画面で Pull Request を作る
#    - base（取り込み先）が ____ になっているか確認
#    - タイトルと説明を書く。説明に #__（Issue 番号）を入れる
#    - 本名・学校名は書かない

# ⑤ 講師のレビューを受ける → 指摘があれば直して commit → push
#    （PR を作り直す必要は ____）

# ⑥ マージされたら、手元の本線を最新にする
git switch ____
git ____
```

---

## ヒント一覧（順番はバラバラ。当てはまるものを選ぶ）

- `-c` … 「新しく作る」の印（create の c）。作るときだけ付ける
- `-u` … 「この枝の送り先はここ」と教える印。**初回だけ**必要（2 回目以降は `git push` だけ）
- `add` … 変更を選ぶ（第1回で既習）
- `branch` … いまいる枝の一覧を出す。`*` が付いているのが現在地
- `pull` … GitHub 側の最新を手元に持ってくる
- `main` … 本線。PR の取り込み先（base）でもある
- 「ない」 … ⑤ の答え。**同じ枝に push すれば PR は自動で最新になる**

## いま図のどこにいる？

詰まったら、まずこの図で現在地を指さして確認する。

番号は上の手順・黒板の図と同じ①〜⑥。`____` の場所も同じ。

```
main（本線）
  │  ⓪ git ____                              ← いまどの枝にいるか確認
  │
  ├── ① git switch ___ feature/lesson-05-xx   ← 枝を作って乗り移る
  │      │
  │      ├── ② 編集 → git ___ . → git commit -m "#__ ..."
  │      │
  │      └── ③ git push __ origin feature/lesson-05-xx
  │                    │
  │                    ↓
  │              ④ GitHub で PR を作る（base ＝ 取り込み先を確認）
  │                    │
  │                    ↓
  │              ⑤ 講師がレビュー → 直して push（PR は自動更新）
  │                    │
  └────────────────── ⑥ Merge → git switch ____ / git ____
```

> 空いているところの答えは、上の「ヒント一覧」から選ぶ。**この図には答えを書かない**
> （自分で埋めた図が、巡回のときの共通の地図になる）。

## 完成条件（この 4 つが揃ったら合格）

- [ ] `feature/lesson-05-xx` ブランチが GitHub 上にある
- [ ] PR が作られていて、**base が `main`** になっている
- [ ] PR の説明に **Issue 番号**が入っていて、**個人情報が書かれていない**
- [ ] 講師のレビューコメントに **1 回対応して push** できた

> 時間内にマージまで行かなくてもよい。**PR が出せたら今日の目標は達成**。
> 残りのレビュー対応とマージは宿題にする。

## 困ったとき

| 症状 | どうする |
|------|----------|
| `main` にいるまま編集して commit してしまった | まだ大丈夫。`git switch -c feature/...` で今から枝を作れば、その変更ごと持っていける。講師を呼ぶ |
| 「そんな枝は無い」と言われて移動できない | 新しく作るときは `-c` が要る |
| `git push` で「upstream が無い」と怒られる | 初回は `-u origin ブランチ名` を付ける |
| ユーザー名とパスワードを聞かれる | VS Code の左下（アカウントアイコン）から GitHub にサインインする。パスワードは使えない仕組み |
| PR の base を間違えた | PR 画面の base のプルダウンから `main` を選び直せる。作り直さなくてよい |
| レビューをもらった。PR を作り直す？ | **作り直さない。** 同じ枝に commit → push すれば PR が自動で最新になる |
| ブランチ名にスペースや日本語を入れてしまった | 英数字とハイフンだけにする。講師を呼んで作り直す |

> エラーが出たら、**メッセージの 1 行目だけ**を読んで講師に伝える。全部読まなくてよい。

---

## 終わったあと

- マージ済みの `feature/...` ブランチは消してよい（GitHub に「Delete branch」ボタンが出る）。
- ⚠️ **`main` と `answer/*` ブランチは消さない。** 本線と講師の模範解答。
