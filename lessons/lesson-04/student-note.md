## 1. 状態（じょうたい / state）って何？

- **状態 = プログラムが「今どうなっているか」を覚えている値。**
  - カウンターの「今 3 回押された」
  - トグルの「今は開いている」
  - フォームの「今 2 件登録した」
- 覚えておく場所は **変数**。あとで書き換わるので `const` ではなく **`let`** を使う。

```js
let count = 0; // ← これが状態。押されるたびに書き換わる
```

### Arduino との比べっこ（今日の目玉）

Arduino でボタンを押した回数を数えるとき、`int count = 0;` を `loop()` の **中** に書くと、
毎回 0 に戻ってしまって数えられなかった。**`loop()` の外**に置くと値が残る。

> このように `loop()` や関数の **外** に置いて、プログラムのどこからでも見える変数を
> **グローバル変数**（global = 全体の）と呼ぶ。板書に出てくる言葉なので覚えておこう。

```
Arduino                          JavaScript
------------------------------   ------------------------------
int count = 0;   ← loop の外     let count = 0;   ← 関数の外（状態）
void loop() {                    plusButton.addEventListener("click", () => {
  count = count + 1;               count = count + 1;   ← 状態を変える
  lcd.print(count);                showCount();         ← 画面を描き直す
}                                });
```

> **JS も同じ。`addEventListener` に渡す関数の中で `let count = 0;` と書くと、クリックのたびに 0 に戻る。**

## 2. 今日ずっと使う 3 ステップ

```
① 状態を持つ            let count = 0;
② イベントで状態を変える   count = count + 1;
③ 画面を描き直す         countLabel.innerText = count;
```

- ② と ③ は **別の仕事**。ここが今日いちばん多いつまずき。
- **「変数は変わったのに画面が変わらない」= ③ を忘れている。**
- 迷ったら `console.log(count)` を入れて、値が変わっているか先に確かめる。

### 表示更新は関数にまとめる（第3回の応用）

③ を毎回書くと散らかる。**名前を付けた関数にまとめて、状態を変えた直後に必ず呼ぶ。**

```js
function showCount() {
  countLabel.innerText = count; // 状態を画面に映すのが仕事
}
```

- 「増やす」「減らす」「リセット」とボタンが増えても、**画面を書き換える場所は 1 か所だけ**で済む。
- これが宿題（リセット / 5 ずつ増やす）で効いてくる。

### 変数が「正」、画面はそのコピー

- 画面の文字（`innerText`）を読んで計算しない。**本物は変数 `count`。**
- 画面から読むと **文字列** になるので、`"3" + 1` が `"31"` になる事故が起きる。

## 3. 見た目を切り替える: `classList`

CSS 側で「この名札（クラス）が付いていたらこう見せる」を決めておく。

```css
.hidden {
  display: none; /* 名札が付いたら消える */
}
```

JS からは 3 つの操作ができる。今日の主役は `toggle`（トグル）。

```js
panel.classList.add("hidden");    // 名札を付ける（消す）
panel.classList.remove("hidden"); // 名札を外す（出す）
panel.classList.toggle("hidden"); // 付いてたら外す、外れてたら付ける（切替）
```

- **`toggle`（トグル）= 交互に切り替える**という意味。押すたびに ON / OFF が入れ替わる。
- 渡すのは **`"hidden"`**。CSS で書く `.`（ドット）は付けない。
- 第 2 引数で ON / OFF を指定することもできる: `classList.toggle("error", true)` は **必ず付ける**、`false` は **必ず外す**。

### 真偽値をひっくり返す `!`

```js
let isOpen = true;
isOpen = !isOpen; // true ↔ false が入れ替わる
```

- Arduino で LED を交互に点滅させた `ledState = !ledState;` と同じ考え方。
- 見た目（`classList`）だけでなく、**状態の変数も一緒にひっくり返す**のを忘れない。

## 4. フォーム検証（バリデーション）

**検証（バリデーション）= 入力が使える形か確かめること。** 入力をそのまま信じない。

### 入力欄の値は `.value`

```js
const text = sensorInput.value; // 打たれた文字（必ず文字列）
```

- `<p>` や `<span>` は `innerText`、**`<input>` だけは `.value`**。ここが第2回からの差分。

### 空かどうかを調べる

```js
if (text === "") {
  // 空だった
}
```

- **`===` は「同じ？」の比較、`=` は「入れる」代入。** `if (text = "")` と書くと壊れる（今日の事故ポイント）。

### スペースだけの入力は `trim()` で潰す

- `"   "` は `""` ではないので、そのままだとすり抜ける。
- **`trim()`（トリム）= 前後の空白を取り除く。**

```js
const text = sensorInput.value.trim(); // 最初から trim しておくと安全
```

### エラーは「出す」＋「消す」がセット

OK のときにエラー文言を消し忘れると、直したのに赤いままになる。

```js
function checkInput(text) {
  if (text === "") {
    errorMessage.innerText = "センサー名を入力してください";
    return false; // 使えない
  }
  errorMessage.innerText = ""; // ← エラーを消す。これを忘れない
  return true; // 使える
}
```

- 第3回の `isHot(temp)` と同じく、**`true` / `false` を返すだけの関数**。`filter` に渡したあれと同じ形。
- 呼ぶ側は「ダメなら先に進まない」と書く: `if (checkInput(text) === false) { return; }`
- 検証が通ったら、また今日の 3 ステップに戻る（**状態を変える → 画面を描き直す**）。
