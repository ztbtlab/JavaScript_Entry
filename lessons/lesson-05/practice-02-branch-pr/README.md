# 練習2: ブランチを切って PR を出す

**今日の本命。** 書き換えるコードは 1 行だけで、目的は
**Git / GitHub の手順を自分の手で 1 周させる**こと。

## 問題

1. `profile.js` の `favoriteThing` を、**自分の好きなもの**に書き換える
2. その変更を、**自分で作ったブランチ（枝）から PR（プルリクエスト）で提出**する
3. 講師のレビューコメントに **1 回対応**して、もう一度 push する

> ⚠️ `profile.js` に書くのは **「好きなもの」**（部活・食べ物・センサー・ゲームなど）。
> **名前・学校名・住所・SNS のアカウント名は書かない。**
> このリポジトリは **Public（世界中から読める）**。コミットメッセージや PR の文章も同じ。

## ファイルの役割

| ファイル | 役割 |
|----------|------|
| `steps.md` | **穴あきコマンド手順書**。これを埋めながら進める（今日のメイン） |
| `profile.js` | **書き換えるのはここだけ**。`export const favoriteThing = "____";` の 1 行 |
| `main.js` | `profile.js` から `favoriteThing` を `import` して画面に出す。**完成済み・読むだけ** |
| `index.html` | `<script type="module" src="main.js"></script>` 済み。**完成済み・読むだけ** |
| `style.css` | 見た目。触らなくてよい |

## 動かし方

VS Code で `index.html` を右クリック → **Open with Live Server**。
`profile.js` を書き換えて保存すると、画面の文字が変わる。

ダブルクリックで開く（アドレスが `file://`）と `import` が動かないので注意（練習1 と同じ）。

## 進め方

1. まず Live Server で開いて、`____` がそのまま表示されることを確認する
2. `steps.md` を開き、`____` を埋めながら **上から順に**実行する
3. ② のところで `profile.js` を書き換える（保存すると画面が変わる）
4. PR を作ったら講師に伝える。レビューコメントが付く
5. 指摘に対応して、**同じブランチで** commit → push（PR は自動で最新になる）

> **PR を作り直す必要はない。** ここは全員が誤解するところ。
> 同じ枝に push すれば、PR の中身は自動で新しくなる。

## 覚えるコマンドは 3 つだけ

```bash
git switch -c feature/lesson-05-xx       # ① 枝を作って移動（-c は create の c）
git add .                                 # ② 変更を選ぶ（第1回で既習）
git commit -m "#XX profile を更新"        # ② メッセージを付けて保存（Issue 番号を入れる）
git push -u origin feature/lesson-05-xx   # ③ GitHub に送る（初回だけ -u が要る）
```

いま自分がどの枝にいるかは `git branch`、または VS Code の左下でも確認できる。

## チェックポイント（完成条件）

- [ ] **ブランチ**: `feature/lesson-05-xx` が GitHub 上にある
- [ ] **PR**: PR が作られていて、**base（取り込み先）が `main`** になっている
- [ ] **説明**: PR の説明に **Issue 番号**（`#XX`）が入っている
- [ ] **安全**: PR・コミットメッセージ・`profile.js` に**個人情報が書かれていない**
- [ ] **往復**: 講師のレビューコメントに **1 回対応して push** できた

> 時間内にマージまで行かなくてもよい。**PR が出せた時点で今日の目標は達成**。
> レビュー対応とマージは宿題に回してよい。

## デバッグのコツ

- エラーが出たら、**メッセージの 1 行目だけ**を読んで講師に伝える（全部読まなくてよい）。
- 「いま図のどこにいるか」を先に確認する（`steps.md` に図がある）。コマンドの暗記より現在地が大事。
- push できたら GitHub の画面を開く。黄色い帯に **「Compare & pull request」** ボタンが出ているはず。
- PR の説明は 2 行でよい。**「何を変えたか」「どこで迷ったか」**。

## ⚠️ 今日から提出のしかたが変わる

| | 第2〜4回 | 第5回以降 |
|---|---|---|
| 提出先 | 講師が用意した `answer/lesson-0X-YY-*` ブランチ | **自分で切った `feature/...` ブランチ + PR** |
| `answer/` の役割 | 提出先 | **講師の模範解答置き場**（見てよいが提出には使わない） |

この練習には `answer/` フォルダが無い。**答えは人によって違う**（自分の好きなもの）ので、
模範解答があるのは「手順」の方＝ `steps.md` のヒント一覧。

⚠️ **`main` ブランチと `answer/*` ブランチは消さないこと。**

## 用語メモ

- **ブランチ（枝）**: 本線を壊さずに作業するためのコピー。Arduino でいえば「別のブレッドボードで試す」。
- **PR（プルリクエスト）**: 「この変更を本線に入れてください」という依頼。話し合いの場でもある。
- **レビュー**: 講師が付けるコメント。ダメ出しではなく「もっと良くする提案」。
- **マージ**: PR の内容を `main`（本線）に取り込むこと。
