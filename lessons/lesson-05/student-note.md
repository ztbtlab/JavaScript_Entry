## 1. なぜファイルを分けるの？

第4回まで、カウンターのコードは `main.js` に全部入っていた。よく読むと、**2 種類の仕事**が混ざっている。

- **計算の仕事**: `count + 1` を作る、`0` に戻す
- **画面の仕事**: `document.getElementById(...)`、`countLabel.innerText = ...`

考えることが別なので、**ファイルも別にする**。分けると嬉しいことは 3 つ。

1. 直したい場所をすぐ探せる
2. 計算だけ取り出して確かめられる（画面が無くても試せる）
3. 何人かで作るとき、別々のファイルを担当できる（← 今日の後半の PR につながる）

> Arduino の類推: 「センサーを読む関数」「LED を光らせる関数」を作って、`loop()` がその 2 つを呼ぶ。あの形と同じ。JS では **`main.js` が `loop()` の役** になる。

### 今日の 3 つのファイル

| ファイル | 担当 | 目印 |
|----------|------|------|
| `logic.js` | **計算だけ** | `document` が 1 回も出てこない |
| `ui.js` | **画面だけ** | 計算しない。渡された値を映すだけ |
| `main.js` | **司令塔** | 状態（`count`）を持ち、上の 2 つを呼んでつなぐ |

## 2. `export` と `import`（貸し出す・借りてくる）

```js
// logic.js — 計算だけ。画面のことは何も知らない
// export を付けると「他のファイルに貸し出す」印になる
export function increment(count) {
  return count + 1;
}

export function decrement(count) {
  return count - 1;
}

export function reset() {
  return 0;
}
```

```js
// ui.js — 画面に出すことだけ。計算はしない
const countLabel = document.getElementById("count");

export function showCount(value) {
  countLabel.innerText = value; // 渡された値を映すだけ
}
```

```js
// main.js — 状態を持ち、2 つのファイルを呼び出してつなぐ司令塔
import { increment, decrement, reset } from "./logic.js";
import { showCount } from "./ui.js";

let count = 0; // 状態はここが持つ（第4回と同じ）
```

- **`export`** = 貸し出す印。付け忘れると、借りる側でエラーになる。
- **`import { 名前 } from "./ファイル名.js";`** = 借りてくる。
  - **波カッコ `{ }`** … 名前を指定して借りるときに要る
  - **`./`** … 「同じフォルダの」という意味
  - **`.js`** … ブラウザでは拡張子まで正確に書く

### 第4回からの変化: `showCount()` に引数が付く

前回の `showCount()` は**引数なし**で、外にある `count` を直接読んでいた。
分割すると `count` は別ファイル（`main.js`）にあるので、**`showCount(count)` と値を渡す形**に変える。

> **ファイルをまたぐときは、変数を直接見ずに引数で渡す。** これが今日の考え方。

## 3. `<script type="module">`（今日の最重要の 1 行）

```html
<!-- これまで -->
<script src="main.js"></script>

<!-- 今日から -->
<script type="module" src="main.js"></script>
```

- **`type="module"` を付けて初めて `import` が使える。** 付け忘れると `import` の行でエラーになる。
- `type="module"` は「HTML を読み終わってから実行」になるので、`defer` は書かなくてよい。

### ⚠️ ダブルクリックで開くと動かない

`index.html` をダブルクリックして開く（アドレスが `file://` で始まる状態）と、モジュールは動かない。Console にこんなエラーが出る。

```
Access to script at 'file:///.../logic.js' from origin 'null' has been blocked by CORS policy
```

- 理由: ブラウザが安全のため、ファイルを直接開いた状態では別ファイルの読み込みを禁止しているから（**CORS**＝コルス。別の場所のファイルを読んでよいか決めるブラウザの安全ルール）。今はここまでの理解で十分。
- **必ず VS Code の Live Server で開く**: `index.html` を右クリック →「Open with Live Server」。アドレスが `http://127.0.0.1:5500/...` になっていれば OK。

### もう 1 つの変化: モジュールの中の変数は外から見えない

- `type="module"` にすると、そのファイルで作った変数は**そのファイルの中だけのもの**になる。
- なので DevTools の Console に `count` と打っても `count is not defined` になる（前回までは見えていた）。
- 中身を見たいときは、コードの中に `console.log(count);` を書く。
- これは不便ではなく**安全のため**（他のファイルと名前がぶつからない）。

## 4. ブランチと PR（今日の後半）

### ブランチ = 本線を壊さずに作業する枝

- `main`（メイン＝本線）は「いつでもちゃんと動く状態」を保ちたい場所。
- でも作っている途中は動かない時間がある。→ その途中経過を `main` に置きたくない。
- だから**枝（ブランチ）を作ってそこで作業する**。

> Arduino の類推: 動いている回路はそのままにして、**別のブレッドボードで試す**。うまくいったら本番に反映する。

### 流れの図（この図のどこにいるかを常に意識する）

```
main（本線）
  │
  ├── git switch -c feature/xxx      ← ① 枝を作って乗り移る
  │      │
  │      ├── 編集 → git add → git commit   ← ② いつも通り保存
  │      │
  │      └── git push -u origin feature/xxx ← ③ GitHub に送る
  │                    │
  │                    ↓
  │              GitHub で PR を作る        ← ④ 「見てください」の依頼
  │                    │
  │                    ↓
  │              講師がレビュー → コメント   ← ⑤ 指摘をもらう
  │                    │
  │                    ↓ 直して commit → push（PR は自動で更新される）
  │                    │
  └────────────────── Merge                 ← ⑥ 本線に取り込む
```

### 覚えるコマンドは 3 つだけ

```bash
git switch -c feature/lesson-05-xx       # ① 枝を作って移動（-c は create の c）
git add .                                 # ② 変更を選ぶ（第1回で既習）
git commit -m "#XX カウンターを分割"       # ② メッセージを付けて保存（Issue 番号を入れる）
git push -u origin feature/lesson-05-xx   # ③ GitHub に送る（初回だけ -u が要る）
```

> **`xx` は講師が配る自分の記号**（出席番号など）に置き換える。
> みんなが同じブランチ名を使うとぶつかってしまうので、**枝の名前は 1 人 1 つ**にする。

- いま自分がどの枝にいるかは `git branch`、または VS Code の左下でも確認できる。
- `-u` は「この枝の送り先はここ」と教える印。**2 回目以降は `git push` だけでよい**。

### PR（プルリクエスト）とは

- 日本語にすると「**この変更を本線に入れてください、という依頼**」。
- **タイトル**（何をしたか 1 行）と **説明**（なぜ・どう変えたか）を書く。
- 説明に `#XX`（Issue 番号）を書くと、その課題と自動でつながる。
- PR は**メッセージのやり取りができる場所**でもある。迷ったところを書いてよい。

### レビューされたら

- 講師がコメントを付ける。指摘は「ダメ出し」ではなく「もっと良くする提案」。
- 直したら、**同じブランチで** `git add` → `git commit` → `git push` するだけ。
  **PR は自動で最新になる**。作り直さなくてよい（← 全員が誤解するところ）。

### マージされたら

```bash
git switch main
git pull
```

- マージ済みの `feature/...` ブランチは消してよい（GitHub に「Delete branch」ボタンが出る）。
- ⚠️ **`main` と `answer/*` は消さない。** これは本線と講師の模範解答。

## 7. 今日のまとめ 3 行

1. **役割でファイルを分ける。`logic.js` は計算（`document` を書かない）、`ui.js` は画面、`main.js` は司令塔。**
2. **`export` で貸し出し、`import { 名前 } from "./logic.js";` で借りる。HTML には `type="module"`、開くのは Live Server。**
3. **ブランチを切って PR を出す。レビューを受けたら同じ枝に push すれば PR は自動で最新になる。**
